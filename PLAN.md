# План работы

## Контекст

Приложение переведено с портала госоргана (заявки на оплату, ИПФ, специфики, Казначейство,
интеграции с e-Qyzmet/ОАГ, вход по ИИН) на портал бухотдела коммерческой компании.

Причина смены: прежняя модель описывала процесс согласования суммы, но не документ. Бухгалтер
не мог сделать в приложении ничего из того, чем занят рабочий день.

## Проверено

Типы: `tsc --noEmit` — чисто. Сборка: `vite build` — успешно.

Прогон API — 76 проверок, все зелёные.

Документооборот (45): авторизация и права ролей, видимость документов для
инициатора, все фильтры реестра, пагинация, итоги, CSV с BOM, расчёт НДС 12/112, полный маршрут
согласования с возвратом, порог главбуха, запрет проводки без оригинала, частичная и полная
оплата с пересчётом остатка, массовое действие с пропуском невалидных, аудит, вложения
(загрузка / скачивание / whitelist / доступ к чужому документу), валидация БИН и дубли.

Закрытие месяца (31): доступ по ролям, чек-лист и ответственные, отказ по блокировкам и по
невыполненным пунктам, закрытие чистого периода, все пять путей заморозки (правка, переход,
оригинал, учёт, заведение задним числом), повторное открытие с причиной и разморозка.

Найден и исправлен баг: `CHIEF_APPROVAL_THRESHOLD` был задан в тенге, а суммы хранятся в
тиынах — реальный порог получался 10 000 ₸, и очередь главбуха дублировала общую.
