# Портал бухотдела

Веб-приложение для бухгалтерии компании: сбор первички, согласование, оплаты и контроль полноты документов.

## Что это и чем не является

Это **входной контур бухгалтерии**, а не замена учётной системе. Проводки, регистры и налоговые
формы остаются в 1С; сюда забирается то, что 1С делает плохо:

- сбор первички от сотрудников вне бухгалтерии (менеджер в 1С не пойдёт);
- согласование с возвратом на доработку и перепиской по документу;
- контроль «где оригинал» и «что мешает закрыть месяц»;
- реестр на оплату и разнесение платежей.

## Ключевые решения

**Четыре независимых статуса документа.** Согласование, оригинал, оплата и учёт живут отдельно
друг от друга. Самое частое проблемное состояние в бухгалтерии — «оплачен, но оригинала нет» —
одномерным статусом невыразимо.

**Участки.** Бухгалтерия работает не общим списком, а по участкам (поставщики, банк, зарплата,
ТМЗ, реализация, налоги). У документа есть ответственный бухгалтер, у бухгалтера — своя очередь.

**Роль инициатора.** Сотрудник вне бухгалтерии заводит счёт или авансовый отчёт сам, видит только
свои документы и их статус. Если первичку вводит бухгалтер, приложение не окупается.

**Все суммы — в тиынах** (целые числа). Форматирование в тенге — только в `src/lib/format.ts`.

## Технологии

- **Фронтенд:** React 19, TypeScript, Vite, Tailwind CSS 4, lucide-react
- **Бэкенд:** Express, better-sqlite3, tsx
- **Общий домен:** `shared/domain.ts` — типы и константы, импортируются и сервером, и клиентом

## Требования

Node.js 22+ (better-sqlite3 — нативный модуль, при смене мажорной версии нужен `npm rebuild`).

```bash
sudo dnf install nodejs npm   # Fedora
npm install
```

## Запуск

```bash
npm run server    # терминал 1 — API на :3001
npm run dev       # терминал 2 — фронтенд на :3000
```

Открыть http://localhost:3000

## Экраны

| Экран | Что делает |
|---|---|
| **Рабочее место** | Очереди «что требует меня сейчас», сводка по периоду, последние изменения |
| **Документы** | Плотный реестр: фильтры в URL, массовое согласование, сумма по выделенным, выгрузка в CSV |
| **Карточка документа** | Реквизиты, вложения, четыре статуса, обсуждение, полная история действий |
| **Контрагенты** | Сальдо, долг, документы без оригиналов |
| **Карточка контрагента** | Реквизиты, договоры, вся история работы |
| **Оплаты** | Реестр на оплату с отбором и разнесением, история платежей |

## Роли и права

| Действие | Инициатор | Бухгалтер | Главбух | Руководитель |
|---|:---:|:---:|:---:|:---:|
| Видит документы | только свои | все | все | все |
| Заводит документ | ✓ | ✓ | ✓ | — |
| Отправляет на проверку | ✓ | ✓ | ✓ | — |
| Согласует до 1 000 000 ₸ | — | ✓ | ✓ | — |
| Согласует от 1 000 000 ₸ | — | — | ✓ | — |
| Возвращает на доработку | — | ✓ | ✓ | — |
| Отклоняет | — | — | ✓ | — |
| Ведёт оригинал и учёт | — | ✓ | ✓ | — |
| Проводит оплаты | — | ✓ | ✓ | — |
| Заводит контрагентов | — | ✓ | ✓ | — |

Возврат и отклонение требуют обязательного комментария — он попадает в карточку документа
и виден инициатору.

## Структура

```
shared/
  domain.ts             — роли, участки, типы документов, статусы, маршрут согласования

server/
  index.ts              — Express, порт 3001
  db.ts                 — схема, миграция по версии, seed, аудит
  auth.ts               — сессии, роли, rate-limit, CORS
  routes/
    auth.ts             — вход по почте
    documents.ts        — реестр, фильтры, маршрут, массовые действия, CSV
    counterparties.ts   — контрагенты и сальдо
    payments.ts         — реестр на оплату, платежи с разнесением
    workspace.ts        — очереди рабочего места и справочники
    attachments.ts      — загрузка и выдача файлов
  data/                 — SQLite и вложения (в git не попадают)

src/
  pages/                — Workspace, Documents, DocumentDetail, Counterparties,
                          CounterpartyDetail, Payments, Login
  components/           — StatusChips, DocumentFormModal, ui/
  services/             — api, auth, documents, directory
  lib/format.ts         — деньги, даты, склонения
```

## Сброс базы

Удалить `server/data/` — при следующем запуске схема и seed создадутся заново.
Схема версионируется (`SCHEMA_VERSION` в `server/db.ts`): при её повышении база пересоздаётся
автоматически.
