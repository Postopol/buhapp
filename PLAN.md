# План работы

## Контекст

Приложение переведено с портала госоргана (заявки на оплату, ИПФ, специфики, Казначейство,
интеграции с e-Qyzmet/ОАГ, вход по ИИН) на портал бухотдела коммерческой компании.

Причина смены: прежняя модель описывала процесс согласования суммы, но не документ. Бухгалтер
не мог сделать в приложении ничего из того, чем занят рабочий день.

Разбор выписки и сопоставление (65, модульно, без API): суммы с пробелами, неразрывными пробелами
и символом тенге, даты в трёх форматах с проверкой по календарю, нормализация номера, разделители
таб / «;» / двойной пробел, пустые колонки не сдвигают суммы, итоговые строки не считаются
документами, ни одна строка не исчезает молча, сопоставление по номеру, по сумме и по хвосту цифр,
запрет ложного совпадения оплаты со счётом и по короткому номеру, отказ от неоднозначной пары,
недопустимость двойного занятия одной строки.

Найдены и исправлены баги:
- `CHIEF_APPROVAL_THRESHOLD` был задан в тенге, а суммы хранятся в тиынах — реальный порог
  получался 10 000 ₸, и очередь главбуха дублировала общую.
- Поиск не работал ни по одному кириллическому запросу: `LOWER` в SQLite знает только латиницу,
  поэтому «Астана» и «СЧ-4471» не находили ничего. Заменён на свою функцию `rulower`.
- Выгрузка акта падала с 500: кириллический номер акта попадал в HTTP-заголовок
  `Content-Disposition`, где допустим только ASCII.

Найдены и исправлены при ревью самих актов сверки: номер выдавался от количества актов, а не
от максимума, и после удаления из середины упирался в UNIQUE; переход «Подписан с протоколом»
был недостижим, потому что проверка совпадения сальдо не делала исключения для протокольного
подписания; повторный импорт сносил строки, заведённые бухгалтером вручную; пересборка снимка
теряла всю сверку по строкам; история акта отдавалась сырыми строками БД и на экране не читалась;
пустые колонки в выписке сдвигали суммы, и оплата приезжала начислением; итоговые строки
(«Итого», «Сальдо») попадали в акт как документы; строка с суммой в нераспознанном формате
исчезала без следа; сопоставление по короткому номеру и по неоднозначной паре давало ложное
«сходится»; оплата по отклонённому документу выпадала из периода платежа без объяснения.
