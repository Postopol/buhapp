# Портал бухотдела

Веб-приложение для бухгалтерии компании: сбор первички, согласование, оплаты и контроль полноты документов.

## Что это и чем не является

Это **входной контур бухгалтерии**, а не замена учётной системе. Проводки, регистры и налоговые
формы остаются в 1С; сюда забирается то, что 1С делает плохо:

- сбор первички от сотрудников вне бухгалтерии (менеджер в 1С не пойдёт);
- согласование с возвратом на доработку и перепиской по документу;
- контроль «где оригинал» и «что мешает закрыть месяц»;
- реестр на оплату и разнесение платежей.

## Ключевые решения

**Четыре независимых статуса документа.** Согласование, оригинал, оплата и учёт живут отдельно
друг от друга. Самое частое проблемное состояние в бухгалтерии — «оплачен, но оригинала нет» —
одномерным статусом невыразимо.

**Участки.** Бухгалтерия работает не общим списком, а по участкам (поставщики, банк, зарплата,
ТМЗ, реализация, налоги). У документа есть ответственный бухгалтер, у бухгалтера — своя очередь.

**Роль инициатора.** Сотрудник вне бухгалтерии заводит счёт или авансовый отчёт сам, видит только
свои документы и их статус. Если первичку вводит бухгалтер, приложение не окупается.

**Все суммы — в тиынах** (целые числа). Форматирование в тенге — только в `src/lib/format.ts`.

**Закрытие месяца делится на две части.** Блокировки считаются из данных и галочкой не убираются —
они исчезают, только когда исчезает причина (нет оригинала, документ не проведён, платёж не
разнесён). Чек-лист — ручные пункты с ответственными по участкам. Закрыть период можно, лишь когда
чисто и то, и другое; после закрытия документы месяца замораживаются.

**Налоговый календарь считается из правил, а не хранится списком.** Сроки разворачиваются из
`TAX_RULES` на любое окно дат; в БД лежит только состояние «сдано» по тронутым срокам. Дата,
выпавшая на выходной, переносится на понедельник. Праздники не учитываются — их календарь
меняется каждый год и требует отдельного справочника.

**Акт сверки — документ со снимком, а не отчёт на лету.** В момент формирования расчёт
замораживается в акте: удаление платежа или переоткрытие месяца не переписывают то, что уже ушло
контрагенту. Расхождение снимка с текущими данными показывается отдельно, как «дрейф».
Арифметика живёт в одном модуле и повторяет правило сальдо контрагента дословно — акт за всю
историю обязан сходиться с долгом на его карточке до тиына. Начисления режутся по дате документа,
оплаты — по дате платежа, поэтому сальдо на конец одного периода равно сальдо на начало
следующего. Закрытый месяц сверке не мешает: она ничего не меняет в учёте, а сверяются как раз
после закрытия.

**Счётчик сохранённого фильтра считается тем же построителем, что и сам реестр.** Иначе цифра
на плитке и содержимое списка со временем разойдутся. Счётчик всегда в области видимости
смотрящего: общий фильтр «Ждут проверки» покажет бухгалтеру всю очередь, а инициатору — только
его документы.

## Технологии

- **Фронтенд:** React 19, TypeScript, Vite, Tailwind CSS 4, lucide-react
- **Бэкенд:** Express, better-sqlite3, tsx
- **Общий домен:** `shared/domain.ts` — типы и константы, импортируются и сервером, и клиентом

## Требования

Node.js 22+ (better-sqlite3 — нативный модуль, при смене мажорной версии нужен `npm rebuild`).

```bash
sudo dnf install nodejs npm   # Fedora
npm install
```

## Запуск

```bash
npm run server    # терминал 1 — API на :3001
npm run dev       # терминал 2 — фронтенд на :3000
```

Открыть http://localhost:3000

## Проверки

```bash
tests/run.sh          # всё
tests/run.sh 03 05    # только выбранные наборы
```

`tests/run.sh` поднимает отдельный сервер на порту 3101 с чистой базой во временном каталоге,
прогоняет наборы по порядку и суммирует итог. Рабочую базу и запущенный `npm run server`
это не трогает.

Наборы идут по порядку и меняют состояние базы (02 заводит документы, 03 закрывает период),
поэтому порядок значим. Арифметика налоговых сроков проверяется отдельно — модульно, без API.

## Сброс базы

Удалить `server/data/` — при следующем запуске схема и seed создадутся заново.
Схема версионируется (`SCHEMA_VERSION` в `server/db.ts`): при её повышении база пересоздаётся
автоматически.
